How I work with the TRIRIGA platform

I treat a TRIRIGA change as a set of layers that move together: the data model, the forms over it, the state lifecycle and workflows that move records, the queries that read them, and the packages and integrations that carry them out of the system. Lines marked Platform context describe how TRIRIGA itself behaves; everything in first person is my own work.

Data model: Data Modeler

I extend delivered business objects rather than cloning them. At Truist, branch attributes such as ATM count, drive-through lanes, and vault rooms went onto the base object families, so upgrades did not overwrite them. At Citi I added country-specific fields such as local tax and currency the same way.

Each business object also carries a state transition family that defines which actions are valid from which state. A missing transition stays invisible until a workflow tries to use it, which is the fault I traced at Elevance (case study 4).

Forms and user experience: GUI Builder and UX Framework

Most lease and space administration still happens in classic forms, which I extend in GUI Builder with tabs, sections, and query sections that pull related records. For tasks done on a phone or by people outside the core team, I build TRIRIGA UX Framework apps instead: mobile facilities requests for Truist branch staff, space request views for Elevance employees, and lease review screens for Citi's abstraction vendors.

Platform context the UX Framework separates the model (data sources that read and write records) from the view (web components in the browser). Polymer is its long-standing view layer, and Platform 5.0 also supports standard web frameworks such as React, Vue, and Angular.

Business logic: Workflow Builder

Workflows carry the business rules I configure: lease approvals, payment approvals, critical-date notices, escalations to regional managers, and integration triggers. I design each one around the record's state, so it starts on a defined action and leaves the record in a known state. I also mentor junior developers on Workflow Builder debugging and review their workflows before promotion.

Platform context synchronous workflows run inside the user's action, while asynchronous workflows run through the workflow agent, which is where stuck records surface after a release. Workflow instance recording shows the step-by-step path a workflow took; IBM advises against using it in production because of its load and database growth.

Custom code: Java custom tasks

Where standard workflow tasks cannot express the logic, I write Java custom tasks called from Workflow Builder steps: lease escalation calculations at Truist, ASC 842 / IFRS 16 discount-rate lookups by country and lease term at Citi, and a nightly Workday people and organization load at Elevance. Custom Java is code every future upgrade has to carry, so at Truist any request that needed it went to design review first.

Platform context the platform loads custom classes through a ClassLoader record, and a workflow Custom task calls them as ClassLoaderName:ClassName. Custom packages must sit under com.tririga.custom, com.tririga.ps, or com.tririga.appdev.

Queries and reports: Report Manager

One query can feed a report, a form query section, a workflow Query task, and an integration, so a badly scoped query hurts more than one screen. I build portfolio reports such as lease expirations, occupancy by building, and vacant space, and I keep form queries filtered to the record in context. The Truist space allocation slowdown (case study 2) came from a query that loaded every space in a building instead of the selected floor.

Security: Security Manager

At Elevance I defined security groups so regional managers saw only their offices' leases and finance saw lease accounting records, as agreed with the privacy office.

Platform context security groups grant access by module, business object, tab, section, and report, and can restrict records by organization and geography.

Release management: Object Migration Manager

At Truist I keep one OMM package per release with its business objects, forms, queries, and workflows, so missing dependencies show up in test rather than production. At Citi I used OMM to carry the 10.6 to 11.x upgrade through each environment.

Platform context selecting an object for an OMM export does not automatically include its dependents, so a package assembled from memory tends to fail in the next environment.

Data loading: DataConnect and Data Integrator

I have loaded abstracted leases through DataConnect at Citi, and leases, buildings, floors, and spaces through Data Integrator at Elevance. In both cases bad rows were stopped before they became records and sent back to the people who owned the source data.

Platform context DataConnect writes external data into staging tables, and workflows then process staged rows into TRIRIGA records. Data Integrator imports tab-delimited files directly into business objects, and hierarchical records need their parent's full path to land in the right place.

Lease accounting: ASC 842 and IFRS 16

I have configured TRIRIGA Lease Accounting at two enterprises. At Citi I set up classification, discount rates, and amortization for branch and office leases under both ASC 842 and IFRS 16, wrote Java custom tasks for discount-rate lookups by country and lease term, and posted monthly journals to the bank's ledger. The inputs that drive every schedule are the ones I check hardest: commencement date, lease term (including which renewal options count), discount rate, and payment schedule. A wrong commencement date or a rate taken from the wrong date shifts every period after it, which is what case studies 3 and 5 show.

Platform context ASC 842 keeps operating and finance classes for lessees, and the lease liability is discounted at the rate for the lease at commencement. IFRS 16 has a single lessee model, so TRIRIGA generates a finance-lease schedule when IFRS is the selected standard.

Problem-solving case studies

These seven problems from my engagements show how I trace TRIRIGA issues to a root cause. Each problem, cause, and fix is from the project; the Why it happens notes explain the platform mechanics behind them.

1. Lease payments posting twice in SAP (Truist, integration)

Problem. Approved lease payments were posting twice in SAP S/4HANA accounts payable.

Cause. The integration's retry resent records that SAP had already acknowledged.

Fix. I added a sent-flag check on the TRIRIGA Integration Object, so a retry only sends records not yet acknowledged. The duplicates stopped for every landlord.

Why it happens. An outbound integration selects records by query. Unless each record carries a sent or acknowledged marker that the query filters on, a retry cannot tell delivered payments from new ones.

2. Slow space allocation forms (Truist, performance)

Problem. Space allocation forms were slow to open.

Cause. A query association pulled every space in the building when the form loaded.

Fix. I filtered the query to the selected floor, and the form returned to normal response.

Why it happens. Form query sections run as the form loads, so a query scoped to the building grows with the building rather than with the task. IBM's own guidance treats any query over 1,000 milliseconds as too long, a useful bar for form queries.

3. Amortization schedules out of line with finance (Elevance, data migration)

Problem. Lease amortization schedules for migrated leases did not match finance's model.

Cause. Leases had been migrated with commencement dates in the wrong format.

Fix. I corrected the dates and recalculated the schedules, which then matched finance's model before the first close.

Why it happens. The commencement date anchors the lease term, the discount rate, and the first period of every schedule. A date in the wrong format can still load as a valid date, so the error shows up only when schedules are compared side by side, which is why finance reviewed each schedule against the prior model.

4. Lease approvals stuck in queue (Elevance, workflow)

Problem. Lease approvals were queuing and not completing.

Cause. A state transition was missing from the lease state family.

Fix. I added the transition and retested, which released the queued approvals.

Why it happens. The state transition family defines which actions can move a record out of each state. When an approval fires an action with no transition from the record's current state, the record cannot advance and approvals pile up behind it.

5. Wrong right-of-use asset values (Citi, lease accounting)

Problem. Right-of-use asset values were wrong on a set of leases.

Cause. Discount rates were applied by lease start date instead of commencement date.

Fix. I corrected the rate lookup and recalculated the affected leases.

Why it happens. Under ASC 842 the lease liability is discounted at the rate for the lease at commencement, and the right-of-use asset is measured from that liability. When start and commencement dates differ, a lookup keyed on the wrong one can pick a different rate and change both balances.

6. Custom workflows broken by the 11.x upgrade (Citi, upgrade)

Problem. Some custom workflows broke when tested under TRIRIGA 11.x.

Fix. I retested custom workflows and reports in each environment and rebuilt the ones that broke before the production upgrade.

Why it happens. An application upgrade replaces delivered objects, and custom workflows built against the old versions can depend on fields, tasks, or behavior that changed. That is why custom workflows get retested in every environment, not only the first.

7. Orphaned leases and duplicate space assignments (Truist, data quality)

Practice. Before each release I run SQL against the Oracle Database TRIRIGA schema to find orphaned leases and duplicate space assignments.

Why it matters. Bulk loads and integrations create records outside the forms where a user would notice a missing link, so a direct schema check catches them before they reach reports or lease accounting.

  7. Test. SIT and UAT with business users; defects logged with the record, workflow, and expected result. Lease accounting goes live only on finance's sign-off: Elevance held go-live until schedules matched, and Citi's regional finance teams signed off country by country.
